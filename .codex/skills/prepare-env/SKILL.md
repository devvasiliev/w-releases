# Подготовка окружения

Найди checkout tooling по `prepare.sh` и `config/project.json`. Прочитай его
`README.md`, `docs/setup.md` и текущий конфиг. Выполняй настройку штатной командой;
конфигурация хранит выбранный код и реестр репозиториев.

1. Проверь Node.js >=22, npm, Git и Python >=3.11. Для Docker-сервисов проверь
   Docker Compose и доступ к daemon. Установи зависимости checkout через
   `./prepare.sh --install`; недостающие системные инструменты установи доступным
   пакетным менеджером в пределах разрешений пользователя. Если установка требует
   ручного действия, сообщи точную команду.
2. Узнай только недостающие код и название проекта. Сохрани имеющиеся значения,
   если пользователь настраивает существующее окружение. Выполни `--dry-run`,
   проверь явный список checkout и запусти `./prepare.sh --code CODE --name NAME`.
3. Основной сценарий Notion создаёт стандартную базу задач. Узнай URL родительской
   страницы. Попроси пользователя создать internal connection с read/insert/update
   content, предоставить доступ к странице и задать `NOTION_TOKEN` в локальном
   терминале. Секрет нельзя просить отправить в чат. Альтернатива хранения:
   `prepare.sh --token-stdin` читает токен из приватного файла и сохраняет 0600.
4. При авторизованном создании базы выполни
   `./prepare.sh --create-notion --notion-parent PAGE_URL`. Если пользователь дал
   существующую базу, используй `--notion-database URL`; сопоставь неоднозначные поля
   через `--code-property`, `--status-property`, `--parent-property`.
5. Запусти `./prepare.sh --check`, `npm run agents:check` и `npm run notion -- doctor`.
   Покажи код проекта, путь конфигурации и URL созданной базы. Отдельно перечисли
   зависимости или доступ, которые ещё требуют действий пользователя.

При `NOTION_CREATE_OUTCOME_UNKNOWN` прочитай `.project/notion-setup.json`.
Сохрани журнал. Проверь содержимое указанной страницы через доступный read-only
коннектор либо попроси пользователя найти созданную базу. Продолжи с теми же
`--create-notion --notion-parent` и добавь `--notion-database URL` найденной базы.
При сохранённом ID команда продолжит read-back. Новый POST после неизвестного
результата допускается только после проверки отсутствия базы и прямого решения
пользователя удалить этот intent.

Настройка skills ограничена зарегистрированными checkout. Новый сервис сначала
добавь в `config/project.json`. Сервис запускается по собственному README;
доступность Docker сама по себе не подтверждает запуск приложения.
