# Порядок работы

## Идентификатор работы

Читай код проекта из конфигурации. При наличии Notion найди переданную задачу
через `npm run notion -- find CODE-N` и сверь область работы. URL страницы тоже
допустим. Для локальной технической работы используй согласованный с оператором
код `CODE-000`; он не требует карточки Notion. Схема чужой базы и её статусы
определяют доступные операции.

## Владение и изменения

Tooling владеет общими шаблонами, skills и проверками. Releases владеет
составными релизами. Сервисы владеют своим кодом, данными и deploy hooks.
Реестр `config/project.json` ограничивает синхронизацию указанными checkout.
Канонические инструкции находятся в `templates/`, project skills в `.codex/skills/`.
Generated `.codex/rules`, `.agents/skills` и `AGENTS.md` обновляй через sync.

Классифицируй задачу: исправление существующего контракта, внутреннее изменение
или новое поведение. Для нового поведения сначала согласуй требования и приёмку.
Используй OpenSpec, если проект выбрал этот процесс. Требования должны описывать
пользовательский результат и владельца каждого правила.

## Проверки и сдача

Проверь затронутые контракты через штатные команды. Для внешних интеграций
зафиксируй фактически выполненный контур. Fixture-тест не подтверждает доступ
к реальному провайдеру. При отказе сообщи этап, причину и команду продолжения.
Проверь новые файлы вместе с diff. Коммиты и внешние публикации выполняй по
прямой команде оператора.
