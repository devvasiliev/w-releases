# Подключение поставки

Сначала собери приложение штатной командой его репозитория. Подготовь каталог
с обычными файлами и передай его полный путь в `./release pack --source`.
Пример полного выпуска есть в [README](../README.md).

## Скрипт установки

Для файловой поставки выполни `./release init NAME`. Для своего способа установки
создай `distributions/NAME/deploy.sh` и положи рядом нужные вспомогательные скрипты.
`pack` включит их в архив. Имя `NAME` записывается в kebab-case.
Один самостоятельный скрипт можно передать через `pack --hook FILE`.

Система вызывает `bash ./deploy.sh PHASE` из распакованной поставки:

| Фаза | Что должен сделать скрипт |
| --- | --- |
| `preflight` | Проверить доступ и зависимости. Повторный вызов безопасен, состояние не меняется. |
| `deploy` | Сохранить предыдущее состояние, затем установить версию. |
| `verify` | Проверить, что приложение или файлы работают после установки. |
| `rollback` | Восстановить код и конфигурацию после полного или частичного deploy, сохранить данные. |

Сначала система проверяет все ZIP и вызывает preflight. Затем получает общий lock,
повторяет проверки и устанавливает поставки по алфавиту имён. После установки
проверяет весь набор. Ошибка deploy или verify запускает rollback в обратном порядке,
включая поставку, на которой deploy прервался. Если нужен особый порядок обновления
зависимостей, раздели выпуск на совместимые наборы.

Файловый шаблон хранит версии в `<deployRoot>/<name>/versions/<version>-<digest>`
и атомарно переключает `current`. Откат восстанавливает прежнюю ссылку; каталоги
версий и соседние данные сохраняются. Запуск процесса и проверку приложения
добавь в скрипт команды.

## Что получает deploy.sh

Переменные окружения содержат поля `release.env` и контекст установки.
Все пути абсолютные.

| Переменная | Значение |
| --- | --- |
| `W_PROJECT_CODE`, `W_COMPOSE_PROJECT` | Код проекта и тот же код в нижнем регистре |
| `W_RELEASE_SET_ID`, `W_RELEASE_RUN_ID` | Набор поставок и текущая попытка установки |
| `W_DISTRIBUTION_DIR` | Распакованный ZIP |
| `W_DISTRIBUTION_ARCHIVE`, `W_DISTRIBUTION_ARCHIVE_SHA256` | Сохранённый ZIP и его SHA-256 |
| `W_DEPLOY_ROOT`, `W_RELEASES_ROOT` | Каталог установки и корень releases |
| `W_DISTRIBUTION_STATE_DIR` | Постоянное состояние поставки |
| `W_RELEASE_RUN_STATE_DIR` | Состояние этой поставки в текущем запуске; здесь сохрани данные для отката |
| `W_TOPOLOGY_REVISION` | Версия схемы окружения из конфига проекта |

## Формат ZIP

`pack` создаёт `<SET>/<NAME>.zip` с `payload/` и файлами скрипта установки.
Обязательные файлы в корне: `release.env`, `deploy.sh`, `compatibility.json`
и `SHA256SUMS`. Последний содержит SHA-256 всех остальных файлов.
Готовый архив не перезаписывается.

```dotenv
W_DISTRIBUTION_NAME=search-worker
W_DISTRIBUTION_VERSION=1.0.0
W_DISTRIBUTION_COMMIT=0123456789abcdef0123456789abcdef01234567
```

Для Docker можно добавить пару `W_DISTRIBUTION_IMAGE` и `W_DISTRIBUTION_ARCH`
(`linux/amd64` или `linux/arm64`). Загрузку образа и проверку его точного ID
выполняет скрипт поставки.

## Зависимости

При зависимости от других поставок передай `pack --compatibility FILE`:

```json
{
  "schema_version": 1,
  "distribution": "search-worker",
  "supported_topology_revisions": ["1"],
  "ownership_generation": 1,
  "contracts": {"provides": [], "requires": []},
  "database_schema": null
}
```

В `provides` укажи `{ "kind": "api", "name": "search", "major": 1 }`.
В `requires` нужны `provider`, `kind`, `name`, `minimum_major`, `maximum_major`.
Допустимые `kind`: `api` и `event`. Для БД укажи `revision` и `rollback_floor`.
Проверка учитывает новые и уже активные поставки: общий состав должен оставаться
совместимым и допускать откат кода.

## Разобрать сбой

Выполни `./release inspect RUN_ID`. После начала deploy в
`<stateRoot>/runs/RUN_ID/` сохраняются `report.txt`, `result.json` и файлы запуска.
При KILL или сбое хоста автоматический откат может не выполниться. Владелец
поставки восстанавливает её через фазу rollback с сохранённым контекстом запуска.
Пути `stateRoot`, `deployRoot` и таймауты находятся в `config/project.json`.
